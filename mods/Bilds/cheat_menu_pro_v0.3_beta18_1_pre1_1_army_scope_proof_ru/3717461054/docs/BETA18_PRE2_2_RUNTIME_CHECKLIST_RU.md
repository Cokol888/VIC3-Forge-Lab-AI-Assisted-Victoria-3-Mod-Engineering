# beta18-pre2.2 — Runtime checklist: Fleet Target Core Repair

Цель этой сборки — проверить только фундамент точного выбора флота. Новые transfer/flagship/supply-механики в этот gate не входят.

## 1. Чистый старт

1. Полностью заменить текущий каталог мода содержимым beta18-pre2.2.
2. Полностью перезапустить Victoria 3.
3. Открыть Workspace → Армия и флот → Флот → Выбранный флот.

## 2. Прямая диагностика selector

1. Нажать «Выбрать / изменить флот».
2. У каждой строки флота справа должен быть узкий жёлтый маркер — это означает, что `MilitaryFormation.MakeScope` успешно используется как прямой ROOT ScriptedGui.
3. До клика сверху должны отображаться статусы «обработчик ещё не получил выбор» и «точная метка не записана».
4. Нажать на один флот.
5. После клика ожидаются одновременно:
   - «Обработчик формирования получил выбор»;
   - «Точная метка записана»;
   - зелёная линия у выбранной строки.
6. Закрыть picker крестиком.
7. В основной строке должна остаться точная выбранная formation по имени.

## 3. Смена и очистка

1. Если есть два флота, выбрать второй: зелёная линия должна перейти только на него.
2. Нажать «Очистить цель»: имя и marker должны исчезнуть.
3. Повторно выбрать первый флот.

## 4. Exact-operation smoke

1. В «Выбранном флоте» выбрать доступный корпус и +1.
2. Выполнить «Добавить корабли».
3. Проверить, что новый корабль появился именно в выбранном флоте, а не в другом.
4. Повторить после +1 игрового дня.
5. Сделать save/load и проверить отсутствие ghost-target.

## Диагностические исходы

- Жёлтого маркера нет: direct GUI root не формируется.
- Жёлтый есть, но «обработчик» остаётся красным: Execute не принимает прямой formation-root.
- Обработчик зелёный, exact marker красный: эффект стартует, но marker не сохраняется на formation.
- Оба зелёные, но основная строка не меняется: дефект resolver/display после записи marker.
- Всё зелёное, но операция идёт в другой флот: дефект exact-operation resolver.
